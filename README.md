# Task API — FlyRank Week 3 A2

This project continues the Week 2 CRUD API and replaces its in-memory task list with a real SQLite database. The API keeps the same task endpoints while storing data in `tasks.db`, so tasks survive a server restart.

## Why SQLite?

SQLite was chosen because it is a single database file with zero separate-server setup. It is lightweight for this assignment and provides persistence across application restarts.

## Run locally

```bash
python -m venv .venv
# Windows PowerShell
.venv\Scripts\Activate.ps1
# macOS/Linux
source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload
```

Open `http://localhost:8000/docs` for Swagger UI.

`tasks.db` is created automatically next to `main.py`. It is intentionally git-ignored so a fresh clone creates its own local database.

## Database

The `tasks` table contains:

| Column | Type | Purpose |
|---|---|---|
| `id` | INTEGER PRIMARY KEY AUTOINCREMENT | Unique task ID generated by SQLite |
| `title` | TEXT | Task title |
| `done` | INTEGER | Boolean stored as 0/1 |

The app creates the table if it is missing and seeds exactly three example tasks only when the table is empty. Restarting the app does not duplicate the seed rows.

## Endpoints

| Method | Endpoint | Purpose | Success / errors |
|---|---|---|---|
| GET | `/` | API information | 200 |
| GET | `/health` | Health check | 200 |
| GET | `/tasks` | List all tasks | 200 |
| GET | `/tasks/{id}` | Get one task | 200 / 404 |
| POST | `/tasks` | Create a task | 201 / 400 |
| PUT | `/tasks/{id}` | Update a task | 200 / 400 / 404 |
| DELETE | `/tasks/{id}` | Delete a task | 204 / 404 |

## Parameterized SQL

User-controlled values are passed separately through `?` placeholders rather than concatenated into SQL strings. For example:

```sql
SELECT * FROM tasks WHERE id = ?;
```

## Stage 4 SQL query

The query recorded in `docs/sql-example.sql` is:

```sql
SELECT * FROM tasks;
```

It returns every row in the `tasks` table. The same rows should be visible through `GET /tasks` because both views read the same SQLite file.
